## 1. 前言：变量到底是什么

```cpp
int x = 42;
```

| 概念 | 内容 |
|---|---|
| 名字 | `x` |
| 值 | `42` |
| 地址 | 内存里的门牌号，比如 `0x7ffee3a2` |

**名字是给人看的，地址是给机器（CPU）用的。** ⚠️ 原笔记写成了"机器人"。

<a id="s2"></a>
### `&x` 是什么

```cpp
&x      // x 的地址
```

**类型是 `int*`（指向 int 的指针）。**

⭐ **补充：`&` 读作"取地址"，也叫 reference operator。它在表达式里用，不是声明。**

---

<a id="s3"></a>
## 2. 指针是什么

**一个专门用来存"地址"的变量。**

```cpp
int* p;      // p 是一个指针，指向一个 int
```

**图示：**

```
        值          地址
x:    [ 42 ]      0x1000
p:    [ 0x1000 ]  0x2000
```

**p 里装的不是 42，而是"42 住在哪"。**

<a id="s4"></a>
### ⭐ 补充：声明的两种写法

```cpp
int* p;      // 推荐：强调"p 的类型是 int*"
int *p;      // 也行，老代码常见
int* a, b;   // ⚠️ 只有 a 是指针，b 是 int！
```

**最后一行是经典坑：**

```cpp
int* a, b;    // a 是 int*，b 是 int
int *a, *b;   // 两个都是 int*
```

**想声明两个指针，就分两行写。**

<a id="s5"></a>
### ⭐ 补充：指针占多大

| 系统 | `sizeof(int*)` |
|---|---|
| 64 位 | 8 字节 |
| 32 位 | 4 字节 |

**不管指向什么类型，指针本身大小都一样。**

<a id="s6"></a>
## 3. ⚠️ `*` 和 `&` 有两个身份

这是初学者最容易晕的地方：

| 场景 | 符号 | 含义 |
|---|---|---|
| **声明**变量时 | `int* p` | "p 是指针" |
| **使用**变量时 | `*p` | "取 p 指向的值" |
| **声明**变量时 | `int& r` | "r 是引用"（上一讲） |
| **使用**变量时 | `&x` | "取 x 的地址" |

**同一个符号，位置不同，意思不同。**

⭐ **补充：看它在"类型"里还是在"表达式"里。**

```cpp
int* p = &x;    // 左边的 * 是类型；右边的 & 是取地址
*p = 10;        // 这里的 * 是解引用
```

<a id="s7"></a>
## 4. 用指针改值

```cpp
int x = 42;
int* p = &x;

*p = 100;              // 顺着地址改内容

std::cout << x;        // 100   ← x 真的变了
```

**`*p` 和 `x` 指的是同一块内存。**

```
x:  [ 100 ]   ← 通过 p 改的就是这里
p:  [ &x   ]
```

<a id="s8"></a>
### 指针最常见的用途：让函数改到外面的变量

```cpp
void doubleIt(int* p) {
    *p = *p * 2;
}

int main() {
    int a = 5;
    doubleIt(&a);      // 传地址进去
    std::cout << a;    // 10
}
```

<a id="s9"></a>
### ⭐ 补充：三种传参对比

| 传法 | 写法 | 能否改到外面 | 能否为空 |
|---|---|---|---|
| 传值 | `void f(int n)` | ❌ | — |
| 传引用 | `void f(int& n)` | ✅ | ❌ |
| 传指针 | `void f(int* p)` | ✅ | ✅（可以传 nullptr） |

---

<a id="s10"></a>
## 5. 指针 vs 引用

| | 指针 `T*` | 引用 `T&` |
|---|---|---|
| 能不能为空 | ✅ 可以 `nullptr` | ❌ 不能 |
| 能不能换目标 | ✅ 可以改指向 | ❌ 一旦绑定不能换 |
| 语法 | 要写 `*p` / `&x` | 和普通变量一样 |
| 常见用途 | 可为空、集合里存"指向" | 函数参数、不复制 |

**经验法则：**

> **能用引用就用引用；必须"可能为空"或"要换目标"时才用指针。**

<a id="s11"></a>
## 6. 三个必须知道的危险

<a id="s12"></a>
### 6.1 野指针（未初始化）

```cpp
int* p;        // ❌ 里面是垃圾地址
*p = 5;        // ❌ 往随机地址写 → 可能直接崩
```

✅ 正确：

```cpp
int* p = nullptr;     // 明确表示"不指向任何东西"
```

⭐ **补充：`nullptr` 和 `NULL` 的区别**

| 写法 | 类型 | 建议 |
|---|---|---|
| `nullptr` | `std::nullptr_t`（C++11） | ✅ 用这个 |
| `NULL` | 本质是 `0` | ⚠️ 老代码，可能和整数重载混淆 |
| `0` | `int` | ❌ 别用来表示空指针 |

<a id="s13"></a>
### 6.2 空指针不能解引用

```cpp
int* p = nullptr;
std::cout << *p;      // ❌ 崩溃（段错误）
```

✅ 先检查：

```cpp
if (p != nullptr) {
    std::cout << *p;
}
```

<a id="s14"></a>
### 6.3 悬垂指针（dangling pointer）

```cpp
int* p = nullptr;

{
    int x = 42;
    p = &x;           // p 指向块内的 x
}                     // ← x 在这里被销毁

std::cout << *p;      // ❌ x 已经没了，p 指向无效内存
```

**类比：**

> 你记下了"302 房间"，结果酒店把那层拆了。
> 地址还在你本子上，但房间已经不存在了。

⭐ **补充：悬垂指针不一定会立刻崩**

> 那块内存可能还没被别人占用，读出来是"看着正常"的垃圾值。
> **这和 `vector` 越界一样，属于"未定义行为"：可能崩，也可能悄悄错。**

<a id="s15"></a>
## 7. 什么时候指针会失效

| 操作 | 指向元素的指针会怎样 |
|---|---|
| `vector` 扩容（`push_back` 触发 realloc） | ❌ **全部失效** |
| `vector` 中间插入 | ❌ 插入点及之后失效（若扩容则全部失效） |
| `vector` 中间删除 | ❌ 删除点及之后的失效 |
| `set` / `map` 插入、删除**其他**元素 | ✅ 稳定（节点式存储，地址不变） |
| `set` / `map` 删除**该元素** | ❌ 只有它自己的指针失效 |
| 容器本身销毁（离开作用域） | ❌ 全部失效 |
| `erase` 掉那个元素 | ❌ 指向它的指针失效 |

⚠️ 原笔记的"vector 中间插入/删除 → 后面的全部失效"不够精确：
**删除时是"删除点及之后"，插入时是"插入点及之后"。**

⭐ **补充：为什么 `set` / `map` 稳定**

`set` / `map` 的底层是**树节点**，每个元素单独分配内存。
插入/删除别的节点时，已有节点的地址**不会变**。

而 `vector` 是一整块连续内存，扩容时要整体搬家。

<a id="s16"></a>
## 8. ⭐ 悬垂指针：完整例子

<a id="s17"></a>
### 场景：容器出作用域后，指针还在

```cpp
std::set<std::string> students{"Alice", "Bob"};
const std::string* p = &(*students.begin());   // 指向 "Alice"

students.clear();      // 容器被清空
std::cout << *p;       // ❌ 悬垂指针
```

**逐行拆：**

| 代码 | 类型 | 意思 |
|---|---|---|
| `students.begin()` | set 迭代器 | 指向某个元素 |
| `*students.begin()` | `const std::string&` | 那个元素本身 |
| `&(*students.begin())` | `const std::string*` | 它的地址 |
| `*p` | — | 顺着地址取内容 |

<a id="s18"></a>
### ⚠️ 为什么必须加 `const`

`set` 里的元素是**只读的**（不允许改，否则会破坏排序）。
所以指向它的指针必须是 `const std::string*`，不能是 `std::string*`。

```cpp
std::string* p = &(*it);         // ❌ 编译错误
const std::string* p = &(*it);   // ✅
```

<a id="s19"></a>
### ⭐ 为什么有时要存指针，而不是存副本

| 方式 | 代价 |
|---|---|
| `std::queue<std::string>` | 每个字符串**复制一份** |
| `std::queue<const std::string*>` | 只存一个 8 字节地址 |

**代价是：容器一销毁，指针就悬空。**

<a id="s20"></a>
### 回答要点（按这个顺序写）：

1. `set` 被销毁时，它里面的 `std::string` 对象也一起被销毁
2. 队列里的指针**仍然保存着那些旧地址**
3. 这些地址现在指向**已经释放的内存**
4. 再去 `*p` 就是**未定义行为**（垃圾值 / 崩溃）
5. 这个现象叫 **悬垂指针（dangling pointer）**

**图示：**

```
set 存在时：                set 销毁后：
[ "Alice" ] ← p            [ 已释放 ] ← p（还指着这）
[ "Bob"   ] ← p2           [ 已释放 ] ← p2
```

**一句话结论：**

> **指针不拥有对象，它只是"借用地址"。对象死了，指针就废了。**

## 9. ⭐ 指针和迭代器的关系

上一讲说过：

> **不是"迭代器是指针"，而是"指针是一种迭代器"。**

| | 指针 | 迭代器 |
|---|---|---|
| 本质 | 一个内存地址 | 一个"位置"（内部可能就是地址） |
| 来源 | 可以自己造（`&x`） | 只能从容器拿（`begin()`） |
| 能力 | 随机访问 | 视容器而定 |
| 安全性 | 可以乱指 | 不能乱指 |

```cpp
int a[5] = {1, 2, 3, 4, 5};
int* p = a;              // 数组名退化成指针

std::sort(a, a + 5);     // 普通数组也能用 STL 算法
```

**所以指针是"最原始、最强、也最危险"的随机访问迭代器。**

## 10. ⭐ 指针运算（了解即可）

```cpp
int a[5] = {10, 20, 30, 40, 50};
int* p = a;          // 指向 a[0]

std::cout << *p;       // 10
std::cout << *(p + 1); // 20   ← 往后挪一个 int
std::cout << p[2];     // 30   ← 等价于 *(p + 2)
```

**注意：`p + 1` 不是"地址加 1 字节"，而是"加一个元素的大小"。**

```
p      → 0x1000  (a[0])
p + 1  → 0x1004  (a[1])   ← int 是 4 字节
p + 2  → 0x1008  (a[2])
```

⭐ **补充：现代 C++ 里尽量少用指针运算**，用 `std::vector` + 迭代器更安全。

<a id="s23"></a>
## 11. ⭐ 常见错误汇总

| ❌ 错误 | ✅ 正确 | 原因 |
|---|---|---|
| `int* p; *p = 5;` | `int* p = nullptr;` 或先赋值 | 野指针 |
| `int* a, b;` 以为两个都是指针 | 分开写两行 | 只有 a 是 `int*` |
| `std::cout << *p;`（p 可能为空） | 先 `if (p != nullptr)` | 空指针解引用会崩 |
| 返回局部变量的地址 | 返回 `std::string` 值，或用堆/智能指针 | 悬垂指针 |
| `std::string* p = &(*it);`（set） | `const std::string*` | set 元素只读 |
| 存了指针，然后让容器销毁 | 保证容器活得更久 | 悬垂指针 |
| 以为 `p + 1` 是加 1 字节 | 是加 1 个元素 | 指针算术按元素大小 |
